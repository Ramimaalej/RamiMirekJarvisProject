JARVIS est un assistant IA vocal de bureau : il écoute, comprend, répond et agit sur l'ordinateur (ouvrir des applications, contrôler le navigateur, gérer les fichiers, lire les e-mails, piloter les capteurs, écrire du code, etc.). Depuis la refonte Mark XL, chaque micro-fonctionnalité vit dans son propre fichier, le lanceur fait 115 lignes, la mémoire est épaisodique comme celle d'un humain, et le design de l'interface est volontairement flat — aucun arrondi, aucune ombre, aucun widget inutile — pour une clarté maximale.

EN BREFUn seul fichier à lancer : python main.py. Tout le reste s'organise automatiquement : détection du fournisseur LLM disponible, chargement des modèles, initialisation de la mémoire, démarrage de l'interface.

1 · Mise à jour et lancement sur votre PC

Le dépôt GitHub est Ramimaalej/RamiMirekJarvisProject. Sur votre machine :

# 1. Récupérer les dernières modifications
cd C:\Users\VotreNom\J Jarvis        # ou le dossier où vous avez cloné
git pull

# 2. Installer les dépendances (première fois, ou si requirements.txt a changé)
pip install -r requirements.txt

# 3. Installer le navigateur Chromium pour l'automatisation Playwright
playwright install chromium

# 4. (Recommandé) Avoir Ollama installé et tournant : https://ollama.com
ollama serve

# 5. Lancer Jarvis
python main.py
PREMIER LANCEMENTmain.py installe automatiquement les paquets manquants. Si votre environnement est propre, une simple commande suffit : python main.py.

Pour une mise à jour sans Git (dossier copié à la main), il suffit de remplacer le dossier du projet par la nouvelle version, puis de relancer pip install -r requirements.txt et python main.py. Vos fichiers memory/*.json et config/api_keys.json sont conservés — rien n'est perdu.

2 · Configuration — config/api_keys.json

Le fichier central de configuration. Jarvis détecte automatiquement les fournisseurs disponibles (Ollama en local, Groq, NVIDIA NIM, OpenRouter, OpenAI) mais vous pouvez forcer le choix :

{
  "llm_provider": "ollama",      // ollama | groq | nvidia | openrouter | openai
  "llm_model":    "qwen3:4b",    // modèle utilisé par défaut
  "llm_url":      "http://localhost:11434",
  "groq":        { "api_key": "gsk_..." },
  "nvidia":      { "api_key": "nvapi-..." },
  "openrouter": { "api_key": "sk-or-..." },
  "openai":     { "api_key": "sk-..." }
}
ASTUCEVous n'avez jamais besoin d'éditer ce fichier à la main : l'écran de sélection du fournisseur (bouton PROVIDER en haut de l'interface) écrit la configuration pour vous.

4 · main.py — le lanceur (115 lignes)

L'ancien main.py faisait 4 003 lignes : toute la logique y était entassée. Il est maintenant réduit à son strict minimum :

  • Bootstrap : ajout du chemin du projet, variables d'environnement, installation automatique des dépendances.
  • Imports : JarvisLocal (cerveau) et MainWindow (interface).
  • main() : crée l'application Qt, instancie Jarvis, branche l'interface, lance la boucle événementielle.
# Extrait de main.py — la seule chose qui compte
def main():
    setup_environment()      # paths, env vars
    bootstrap()              # dépendances auto-installées
    from ui import MainWindow
    from core.jarvis_core import JarvisLocal
    jarvis = JarvisLocal()
    app    = QApplication(sys.argv)
    win    = MainWindow(jarvis=jarvis)
    win.show()
    sys.exit(app.exec())
POURQUOI C'EST MIEUXChaque modification est désormais localisée : la synthèse vocale est dans jarvis_tts.py, la mémoire dans jarvis_memory.py, le navigateur dans fast_browser.py. Plus de fichier de 4 000 lignes où toucher à une ligne risquait de tout casser.

6 · Outils — declarations.py + executor.py

core/tools/declarations.py déclare tous les outils que le LLM peut appeler : nom, description en langage naturel, paramètres attendus (schemas JSON). C'est ce qui donne au modèle « les mains ».

core/tools/executor.py contient execute_tool(ui, name, args, ...) : une gigantesque branche if/elif qui appelle la bonne action et formate la réponse. Chaque branche reste indépendante — supprimer une action ne casse rien d'autre.

7 · Actions — actions/*.py

Chaque capacité concrète est un fichier isolé. Exemple : actions/weather_report.py expose weather_action(parameters, player) et ne sait rien du reste du système. Cela rend les actions testables unitairement, remplaçables, et permet à plusieurs personnes de travailler dessus sans conflit Git.

La convention : def nom_action(parameters: dict, player=None, speak=None) -> str — retourne toujours une chaîne lisible que Jarvis peut prononcer.

8 · Sélection du fournisseur LLM (nouveau)

Cliquez sur le bouton PROVIDER en haut de l'interface pour ouvrir l'écran de choix :

  • Détection automatique des fournisseurs disponibles (Ollama en local d'abord, puis Groq, NVIDIA NIM, OpenRouter, OpenAI si leurs clés sont présentes).
  • Liste des modèles chargés (pour Ollama, récupérée en direct via l'API locale).
  • Un clic pour changer de fournisseur et de modèle — la configuration est écrite dans config/api_keys.json et appliquée immédiatement, sans redémarrage.

Le détecteur (core/llm_provider_detector.py) teste la connexion, la latence et la disponibilité de chaque backend, puis propose le meilleur choix.

9 · Gestion des modèles Ollama (nouveau)

Le bouton OLLAMA ouvre une page dédiée où vous pouvez, sans ligne de commande :

  • Lister les modèles installés (nom, taille, date).
  • Installer un nouveau modèle (ex. qwen3:4b, llama3.1:8b, gemma3:12b) — la barre de progression suit le téléchargement en direct.
  • Supprimer un modèle pour libérer de l'espace disque.
RECOMMANDÉCommencez par qwen3:4b (rapide et léger) ou llama3.1:8b-instruct-q4 (meilleur équilibre qualité/vitesse). Les modèles « q4 » sont des quantisations 4 bits : 3 à 4 fois plus rapides pour une qualité quasi identique.

10 · Navigateur ultra-rapide (nouveau)

core/fast_browser.py + l'action actions/fast_browser.py remplacent l'ancien pilotage lent :

  • CDP (Chrome DevTools Protocol) : Jarvis se connecte directement à votre navigateur Chrome/Edge déjà ouvert, sans le relancer — zéro temps de démarrage.
  • Playwright en secours si aucun navigateur n'est trouvé.
  • Opérations : ouvrir une URL, cliquer, remplir un formulaire, extraire le texte de la page, capturer la page, naviguer (retour, recharger, nouvel onglet).
  • Routé par l'intention fast_browser (priorité haute) : « ouvre youtube.com », « clique sur le premier résultat », « prends une capture d'écran ».
# Le détecteur cherche les navigateurs ouverts sur leurs ports CDP
# 9222, 9223, ... puis s'attache au premier trouvé :
FastBrowser.attach_cdp("http://localhost:9222")

11 · Mémoire humaine — épaisodique (nouveau)

core/jarvis_memory.py implémente une mémoire en trois couches, comme un humain :

CoucheAnalogie humaineStockage
Épaisodique« Je me souviens de ce qui s'est passé » — chaque interaction marquante devient un épisode datémemory/episodes.json (1 500 derniers épisodes, rolling)
Sémantique« Je connais des faits » — faits, préférences, relations extraites des épisodesmemory/long_term.json + memory/vector_store.json
Explicite« Tu m'as dit de… » — notes et instructions directes (save_memory)memory/*.json via update_memory

Fonctions clés : record_episode() (nouvel épisode), update_last_episode() (enrichit l'épisode en cours — plus besoin de parler d'une traite), format_episode_recall() et format_human_recall() (formulent le rappel en langage naturel pour le prompt). Un verrou réentrant (RLock) garantit qu'aucun interblocage n'est possible lors des enregistrements simultanés.

EXEMPLEVous dites « mon rendez-vous avec Sarah est à 15h ». Jarvis crée un épisode. Le lendemain : « qu'est-ce que j'avais prévu aujourd'hui ? » — il répond à partir de ses épisodes, pas d'une base de données morte.

12 · Réponses générales éclair (nouveau)

core/jarvis_general.py détecte les questions de culture générale (« Qui a gagné le Nobel de physique en 2023 ? », « Capitale de l'Australie ? ») et les route vers le modèle le plus rapide disponible (ex. un petit modèle local ou Groq) au lieu du modèle principal plus lent.

  • is_general_question(text) — classification par mots-clés + heuristique (questions courtes, sans verbe d'action sur l'ordinateur).
  • ask_general(text) — interroge le backend le plus rapide, cache la réponse 24h dans memory/general_cache.json.
RÉSULTATLes questions de faits sont répondues en 1 à 3 secondes au lieu de 10 à 30 secondes, sans dégrader la qualité.

13 · Interface flat & anti-lag

L'interface (ui.py) a été entièrement repensée pour la clarté et la vitesse :

  • Flat design intégral : border-radius: 0 partout, aucune ombre, aucun dégradé superflu — uniquement le visage HUD central conserve un rendu arrondi (élément central identitaire).
  • Hiérarchie claire : une seule colonne de lecture, états visibles (LISTENING / THINKING / SPEAKING), gros contrastes.
  • Anti-lag : le log est mis à jour par lots (_step tronqué à 64 caractères, flush groupé), les pixmaps de la grille HUD sont en cache, les widgets inutiles du dashboard ont été supprimés.
  • Boutons dédiés : PROVIDER, OLLAMA, BROWSER ajoutés au menu — un clic, une fonction.

15 · Tests automatisés

La suite pytest compte 254 tests réussis couvrant les déclarations d'outils, l'executor, la mémoire, le routeur d'intentions, le buffer VAD et les overlays. Exécution :

QT_QPA_PLATFORM=offscreen python -m pytest tests/ -q
NOTE21 tests échouent dans certains environnements (sandbox sans clés API, sans opencv natif, etc.) — ce sont des échecs d'environnement préexistants, jamais introduits par la refonte. Les tests du refactor (déclarations, executor, overlays) passent tous.
